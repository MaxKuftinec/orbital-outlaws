# Orbital Outlaws — 2D Newtonian prototype

A browser-playable multiplayer-*inspired* orbital survival/combat proof of concept. **This build is single-player against two AI raiders; multiplayer is not yet implemented.** No frameworks, packages, or accounts required

## Run it

Open `index.html` in a modern browser. For a convenient single-file edition, open `orbital-outlaws.html` from the download instead (it embeds the same CSS and JavaScript)

For development, run a local HTTP server in this folder:

```bash
python -m http.server 8080
```

Then visit `http://localhost:8080`

## Controls

| Control | Action |
| --- | --- |
| Hold **W** / **↑** | Thrust *prograde*: along your current velocity |
| Hold **S** / **↓** | Thrust *retrograde*: against your current velocity |
| Hold **A** / **←** | Thrust radially *inward*, toward the gravity well |
| Hold **D** / **→** | Thrust radially *outward*, away from the gravity well |
| Hold **Space** | Fire ballistic rounds toward the selected target or manual aim point |
| **P** | Pause / resume |
| Click/tap a ship | Lock that hostile as your target |
| Click/tap empty space | Aim weapons at a fixed world position |
| **Auto-target nearest** | Resume nearest-hostile target lock |
| **Trajectory** | Show/hide your unpowered predicted orbit |
| **− / +** | Zoom |
| **Speed** | Run simulation at 0.5×, 1×, 2× or 4× |

On touchscreen devices, hold the large maneuver and fire buttons below the canvas

## What works

- Newtonian inverse-square gravity from a fixed central body; all ships, ballistic rounds and salvage share it
- Circular initial orbits; coast indefinitely without spending fuel
- Limited fuel only spent during maneuvers, with real thrust-driven changes to orbit
- Predicted unpowered trajectory and telemetry (periapsis, apoapsis, period, altitude, speed)
- Two armed AI raiders, projectile combat, damage and ship destruction
- Salvage crates / floating wrecks, fuel and ammo collection, credits
- A purchasable predictive fire-control upgrade for estimated interception aiming
- Crashing into the central body or losing all hull integrity ends the run
- Keyboard and touch controls, pause, restart, zoom and simulation speed

## Physics (core equations)

Gravity is computed in game units (distance `u`, time `s`):

```
r = (x, y)
acceleration_gravity = -(mu / |r|^3) * r
acceleration_total = acceleration_gravity + acceleration_thrust
mu = 310000 u^3/s^2
```

Bodies are integrated using **velocity Verlet** with fixed 0.015-second substeps. This is substantially more orbit-stable than forward Euler integration. The central body's mass and radius are intentionally game-scaled to produce reasonably short orbital periods. It is a Newtonian sandbox, *not* a physically realistic reconstruction of a named planet/star

A preview is generated by integrating the player's current state **without any future thrust**. A new burn invalidates the preview, so it is recomputed regularly. Predicted laser-like lead aiming is approximate, not a mathematically guaranteed intercept

## Known limitations and next steps

- AI is primitive; future NPCs should use orbital transfer / rendezvous planning instead of occasional heuristic burns
- Projectiles are ballistic. Add guided missiles, lasers and detection ranges later
- The upgrade market has one item. Expand with tanks, engines, navigation and sensor equipment
- There is no docking, piracy transfer mechanic, economy simulation or human networking yet
- Scale / time / gravity parameterization should eventually become configurable
- Accurate ship-to-ship collisions, debris fragmentation and robust continuous collision checks should be added as projectile speeds increase
- Multiplayer requires an authoritative simulation server with deterministic stepping and client prediction/interpolation
- General Relativity and compact objects are **out of scope for this first prototype**, but later geodesic integration could replace Newtonian acceleration near black holes or neutron stars
